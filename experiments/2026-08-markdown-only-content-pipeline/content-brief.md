# 内容简报：半天搭好流水线，第一篇却卡了一周多

## 背景与问题

我读了很多研究报告和前沿资讯，也常常觉得某个方向值得做，但没有真正把尝试落到手上。回头看，这是一种眼高手低：输入不断增加，行动没有形成闭环；想做的事越来越多，却没有沉下心走完「开始尝试、留下记录、整理内容、公开复盘」这些基础步骤。

这不只发生在 AI 领域。很多人想学一项技能、做一个项目或改变一种习惯时，也会卡在同一处：知道得越来越多，第一步却迟迟没有开始。AI 时代，这些基础步骤理应不再是主要拦路虎；它们可以被更低成本地协助完成，但仍需要人决定从哪件事开始，并把过程走完。

于是我把每个想法当作实验：一个目录、一份记录、一次公开。第一个实验是用 AI 搭建这套记录到多平台初稿的流水线。

## 读者痛点 / 叙事线

**作者判断：** 这次不只是在搭一套 AI 内容工具，更是在处理一种常见的停滞：知道得越来越多，却没有把最基础的尝试走完。AI 可以降低开始、记录和整理的门槛，但不能替人完成判断、承担公开的代价，或迈出第一步。

## 关键词与用法

| 关键词 | 类型 | 用法 |
| --- | --- | --- |
| AI agent | 事实对象 | 在背景或 setup 中说明流水线由 agent 协助搭建与运行。 |
| agent harness | 作者类比 | 第一次出现时解释为「把输入、约束、工具、人工确认和反馈串起来的运行环境」；本实验的内容流程属于这一类。 |
| human-in-the-loop | 事实对象 | 指作者确认内容简报、判断结论、审核与发布的必要环节。 |
| AI 原生工作流 | 读者讨论的叫法 | 只用于讨论 AI 降低开始、记录和整理门槛，不暗示发布可无人完成。 |
| 内容流水线 | 事实对象 | 指实验目录、skill、内容简报、审核和平台稿的这一条链路。 |

## 本次发生了什么

流水线骨架半天搭完：`experiment-plan` 负责实验前剧本，`content-forge` 负责把跑完的实验变成内容初稿。实际运行后，第一篇小红书读起来平淡。追查发现，平台配置批评「陈述完事实就转进列表」，模板却硬编码了「结果 / 有效的 / 踩的坑」三段列表；配图规则还依赖机器上不存在的渲染器。校验脚本首次运行抓到 4 处死链。

## 重要困难与作者判断

骨架很快搭完，但从开始到愿意发布第一篇内容，断断续续拖了一周多。原因是我不满意初稿：它看似完整，却不足以吸引人继续读。我因此反复改流程和文案，也越来越不肯发布，几乎回到最初「研究很多、没有真正开始」的状态。

这次只能说明：该生成过程没有自行发现跨文件矛盾，也不能替我判断文章是否值得发；它不能证明所有模型都会如此，更不能推出换模型没有用。我的判断是：初稿必须进入可追溯的审核，不能直接当成成品。

## 超出骨架预期的发现与边界

「平台工具依赖为 0」不等于「发布成本为 0」。注册和维护账号、补真实截图、确认个人观点、手机预览、排版发布和后续维护仍由人承担。视频素材为 0，当前只能生成脚本结构，不能称为可发布视频。

下一版流程应为：实验前确认背景与叙事骨架；实验后先写这类短简报；作者确认事实、观点和公开范围后，再展开为不同平台的稿件，并最多经历 3 轮独立审核和修改。
