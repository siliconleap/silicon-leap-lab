# 纯 Markdown 约定 + Claude Code Skill，能不能撑起一条内容流水线？

## Question

不依赖任何平台工具（n8n / Coze / Dify / Wordware），只用 Markdown 约定加 Claude Code Skill，能不能真的跑起来一条从选题到多渠道初稿的内容流水线？

## Setup

**环境**

- macOS，Claude Code CLI，模型 Opus 5
- git（身份隔离用 `includeIf`）
- 无服务器、无数据库、无第三方平台账号

**被测对象**

双仓结构，全部内容都是纯文本、可版本控制：

| 仓库 | 角色 |
| --- | --- |
| `silicon-leap-forge` | 流水线本体：skill + 平台配置 + 模板 + 约定文档 |
| `silicon-leap-lab` | 实验记录 monorepo，流水线的输入与输出都落在这里 |

流水线由两个 skill 组成：

- `experiment-plan`——输入一句话选题，输出实验目录（`README.md` 七段骨架 + `plan.md` 剧本）
- `content-forge`——输入跑完的实验目录，输出四个平台的内容包（site / github / xiaohongshu / youtube）

配置规模：`platforms/` 4 个平台配置，`templates/` 6 个模板文件，skill 总计 12 个文件。

**任务**

不是 toy example。任务就是这次会话本身：从「不知道要干嘛」开始，到补齐流水线前段、发现并修复两处信息泄露、推送上线。

**判据**

1. 前段 skill 能否从一句话选题产出可照着跑的实验目录
2. 后段 `content-forge` 能否产出四个平台的初稿
3. 全程是否零平台工具依赖

**已知短板**

本次为回溯补记，无录屏、无耗时与 token 记录。详见 `plan.md`。

## Log

起点不是这个仓库，是一种更常见的状态：在工程、AI、行业这些方向上都有涉猎，也想把东西沉淀成内容，但迟迟不开工。工具在比较，方案在研究，最佳实践在找——就是没有公开输出。roadmap 第九节把这个列为最大风险的第一条：「追求完美方案，迟迟不开始」。

破局的办法是给「想尝试的东西」找一个容器——用「实验」把它固定下来：一个目录、一份记录、一次公开。而第一个实验选了什么？用 AI 把这套实验机制本身自动化。

于是有了下面这一场。

开场是一句「check docs and tell me how should i do it」。连要做什么都没定——这本身就是实情：仓库骨架搭好了，约定写好了，但不知道下一步该干嘛。

读 forge 的两份文档，才看清流水线的实际形状：只有中段。`content-forge` 负责「跑完的实验 → 多渠道初稿」，前面的「选题 → 实验怎么设计」和后面的「预览 → 审批 → 发布」都是空的。约定文档里反复出现 WorkBuddy 作为例子，多到看起来像前置依赖——实际上 roadmap 第 568 行明确写着它只是「研究对象，而非基础设施」。一个候选选题被例子的密度顶成了必需品。

顺手撞到的第一个问题：lab README 里指向约定文档的链接，文字写的是 `silicon-leap-forge/docs/...`，实际路径却是 `../silicon-leap/docs/...`，而 `silicon-leap` 这个目录根本不存在。

确认缺口后先补前段，写 `experiment-plan`。设计上抄了 `content-forge` 的边界思路：设计过程，不预设结果。`Log` / `Data` / `What Worked` / `What Failed` / `Conclusion` 五段只留标题，一个字都不许预填——预填等于污染实验，人会不自觉往预设答案上靠。剧本里那张步骤表是核心，「记什么数据」一列不许留空，因为现有约定只说了「至少记这四类数据」，没说什么时候记，而事后是补不出来的。

skill 写完连带改了三处：约定文档加 `plan.md` 一节，`content-forge` 的读取清单带上它，蒸馏摘要加一条「预期落差」——让开跑前的预测和实际结果对照，猜错的地方就是文章最好的开篇。

然后是 skill 放哪的反复。先在 forge 建了 `.agents/skills` 相对软链。轮到 lab 时才发现 lab 下早就有两个软链指向 forge，用的是绝对路径。改成实拷时又踩坑：目标目录已存在，`cp -R` 不是合并而是拷进去，得到 `skills/skills/` 嵌套。

真正的转折在敏感信息扫描。工作区文件本身干净——无绝对路径、无密钥、无邮箱。但查 git 历史时看到：初始 commit 的 author 是本机个人身份，不是早就配好的品牌身份。`git config user.name` 明明写着品牌名，说明那次提交发生在配置之前。仓库从未 push，`--reset-author` 无损修好了。

而刚才那两个绝对路径软链，是同一类问题的另一副面孔：git 把软链目标当 blob 存储，一 push 就等于公开本机用户名和完整目录结构。换成实拷时无意中消掉了，回头看纯属侥幸。

追根因发现全局 git 身份仍是个人身份，两个仓库全靠 repo-local override 挡着，下次新建仓库忘了设就会复发。配了 `includeIf` 按目录自动切身份，用一个临时新仓库实测通过。

收尾时才意识到一件事：这一整场做的全是工具和加固，`experiments/` 目录里还是只有一个 `.gitkeep`。流水线补齐了，实验记录一个都没有。这份文档本身是回溯补记出来的——没有录屏，没有计时。

真正的转折在初稿生成之后。skill 跑通了，四个平台的文案也出来了，然后发现没法看——小红书那篇枯燥得读不下去。

**作者补充（2026-08-21）：** 这次内容的主线定为「收藏夹里躺着一千篇『以后要做』，换不来一次真正的成长」。「一千篇」是概数，不是统计，指的就是下面这种长期状态：收藏、比较、研究，迟迟不动手。

**作者补充（2026-08-15）：** 此前读了很多研究报告和前沿资讯，也常常觉得某个方向值得做，却很少真正把尝试落到手上。回头看，这是一种眼高手低：输入不断增加，行动没有形成闭环；想做的事越来越多，却没有沉下心走完「开始尝试、留下记录、整理内容、公开复盘」这些基础步骤。这不只发生在 AI 领域；很多人想学技能、做项目或改变习惯时，也会卡在同一处。AI 时代，这些基础步骤理应不再是主要拦路虎；它们可以被更低成本地协助完成，但仍需要人决定从哪件事开始，并把过程走完。

流水线骨架半天就搭完了，但这次实验从开始到愿意把内容往外发，断断续续拖了一周多。原因不是代码卡住，而是一直不满意文章内容：初稿越像完整文章，越觉得它不值得发；于是反复打磨流程和文案，反而越来越不肯行动，几乎又落回「研究很多、没有真正开始」的状态。这个人工判断和编辑成本，不能被「平台工具依赖为 0」掩盖。

翻模板才看到根子：它硬编码了「结果 / 有效的 / 踩的坑」三段列表，而同一套配置的另一个文件里正批评这种写法——「陈述完事实就转进列表，没有处境，没有反应，数字没有参照系」。配置在骂模板，模板在违反配置，而两个文件分开看，每一个都是对的。

再往下翻，配图那一节写着「输出 SVG 源文件，由人渲染」。查了这台机器：rsvg-convert、ImageMagick、wkhtmltoimage，一个都没装。这条规则从写下那天起就没有执行的可能。

补救的过程本身也是发现。把确定性的部分沉进脚本之后，校验脚本第一次跑就抓出四处死链——此前那是人工 review 才发现的。配图链路最后落在 HTML → Chrome headless → PNG，零额外安装，HTML 进 git，PNG 是产物。

而所有这些粗浅都指向同一个来源：AI 干活很快，但交出来的是均值。它不会主动想到「这个模板和那份配置自相矛盾」，也不会主动确认「这台机器上到底有没有渲染器」。要拿到均值以上的东西，只能把「不要什么、为什么不要、正例反例长什么样」逐条写进指令里——这一场后半段做的全是这件事。

## What Worked

**纯 Markdown 约定确实能跑。** 判据 3 成立：全程零平台工具，产物全是纯文本、可版本控制、可 diff、可 clone 后直接用。skill 就是一个带 frontmatter 的 Markdown 文件，新增平台只需加一个配置加一套模板，不动主流程。

**「不预填结论」这条边界是对的。** 两个 skill 共用同一条：流水线搬运和格式转换，观点留给人。`experiment-plan` 不填五段结论类标题，`content-forge` 遇到空的 `Conclusion` 不编造只标注待补。这让产物始终是半成品，逼人必须过一遍。

**skill 里写死「先定位到 lab 仓库」救了一次。** 这个 skill 装在 forge，软链后可从任意目录调用，不锚定仓库就会在 forge 里建出 `experiments/`。

**相对软链是可提交的。** `.agents/skills -> ../.claude/skills` 用相对路径，git 存为 symlink 对象，clone 到别的机器依然有效，同时让非 Claude 的 agent 工具也能读到同一份 skill。

**`includeIf` 是根治方案而非补丁。** 按目录前缀自动切 git 身份，不再依赖每个仓库手动设 local config。

## What Failed

**生成物有完整的外观，内容却是空的。** `experiment-plan` 写出来带 frontmatter、分步流程、硬约束清单，读起来像个成熟的 skill；四个平台配置也齐全，每个都有 Role、Emphasis、Layout Rules、验收清单。但真的跑出 `drafts/` 才发现：小红书模板硬编码了「结果 / 有效的 / 踩的坑」三段列表，正是同一份平台配置自己批评的「陈述完事实就转进列表」；配图整节只写了「输出 SVG 源文件，由人渲染」，而这台机器上 rsvg-convert、ImageMagick、wkhtmltoimage 一个都没装，人根本渲染不了。**结构完整掩盖了内容空洞，而 review 读不出这种空洞——它在结构上是齐的。**

**批准了自己没理解的东西。** 生成这个 skill 只花了一句「可以，写出来」。追问发生在批准之后：`plan.md` 和 `README.md` 差在哪、七段骨架分别什么时候写、为什么不加强制校验、skill 里有没有脚本。而平台适配的粗浅，一直到初稿真的生成出来、读到那篇枯燥的小红书文案才暴露。**理解成本不会消失，只会后置**——批准时省下的追问，在使用时连本带利还回来。后来那套三层职责模型（确定性归脚本、可推断归 agent、决策归人）就是对这件事的直接反应：确定性的部分沉进脚本，人需要理解的表面积才会缩小。

**搭了一整场工具，实验记录仍然是零。** 补前段 skill、修泄露、配身份隔离——每一件都合理，合起来却是典型的「工具先行」：流水线越修越完整，而它要处理的输入一个都没有。roadmap 第九节把「追求完美方案，迟迟不开始」列为最大风险第一条，这一场就是它的实例。

**回溯补记本身就是一次失败。** `plan.md` 应该在开跑前写，本次却是事后还原的。「预期反直觉点」这一节因此只能删掉换成「实际发现」——事后补的预测没有价值。流水线的前段是在这一场里才建成的，所以这次是无法避免的一次性例外，但下一个实验没有这个借口。

**一次性的操作失误，不具普遍性。** `cp -R` 前没检查目标目录是否存在，产生 `skills/skills/` 嵌套；README 里一条指向不存在目录的坏链接。这类失误换个时间不会重复，不值得当成实验结论。但两处信息泄露留下了一个可复用的教训——**配置晚于使用**：`git config` 设在首次提交之后，软链建立时没想过它会进 git。先用后配，已经产生的产物不会自动跟着更新。

**视频渠道交付不了，这是四个渠道里唯一的硬缺口。** 脚本、标题、thumbnail 方案、数据卡都能生成——它们都是纯文本，或者能由纯文本渲染成图。但从 `script.md` 到一条能发的视频，中间每一步都在能力之外：录屏素材为 0，剪辑没有自动化路径，配音和字幕也没有。纯文本这套哲学在前三个渠道成立，到视频这里失效——**视频不是纯文本，也没法由纯文本生成**。按当前技术栈，这一段暂时无解，只能靠人工补齐或者干脆放弃这个渠道。

**录屏为零，但这不是执行不力。** asciinema 在这台机器上从未安装过——「终端用 asciinema 录」这条约定从写下的第一天起就没有执行基础。更根本的是形态变了：实际工作方式是人跟 agent 对话、agent 执行，终端里没有「人的操作过程」可录，录下来只是 agent 的输出流。真正的过程记录是对话本身，而这次没有把它当素材保存。

## Conclusion

> 以下照本人原话整理，**已定稿**，作者确认于 2026-08-19。

**三条判据都成立，但没有一条是全自动成立的。** 前段能从一句话选题产出可照着跑的实验目录，后段四个平台的内容包也确实各不相同，全程零平台工具。但中间的判断、探索和精炼全是人做的：哪个缺口值得补、初稿为什么读不下去、哪句原话该留、结论能说到哪里——这些 AI 给不出来，是我一轮轮试出来的。

这既是上面那个判断的佐证，也是这次实验真正的收获：**这套东西不是省掉人，是把人从确定性的活里换出来，去做只有人能做的判断。** 而做这些判断的过程，本身就是积累。

**AI 干活快，但普通的提示词和 harness 只会换来平庸的结果。** 平庸不是模型的属性，是默认值：生成源于已有数据的统计概率，没有明确约束时自然回归均值，而均值就是平庸。所以换个更大的模型不解决问题，只会得到一个更精致的均值。真正起作用的是把「抗拒平庸」写进指令和约束本身——逐条写清不要什么、为什么不要、正例反例长什么样。**打磨的地方不在产物上，在指令上。**

**真正卡住我的不是 AI，是我自己。** 骨架半天搭完，第一篇却拖了一周多。初稿不满意就反复改，越改越不肯发布，几乎回到「迟迟不开工」那个起点——这个实验差点变成它要解决的那个问题的例证。

**所以这次真正学到的是一句话：不苛求完美，不甘愿平庸。** 两头都是失败：苛求完美就永远不发布，甘愿平庸就发了也没人看。路在中间，而且要靠反复打磨才走得出来。

**这是真实的经历，不是方案介绍。** 这里写下的每一条都来自这次实际跑完的过程：失败是真失败，卡了一周多是真卡了一周多，数字来自记录而不是估计，引用的原话带时间戳可回查。它不是从网上拼凑的最佳实践综述，也不是把一套工具包装成产品在宣传。做不到的地方就写做不到——视频那一段判定为做不出来，就照实写了做不出来；试过一版仍然没成，也照实写没成。

**边界。** 样本量为 1。这次只能说明该生成过程没有自行发现跨文件矛盾，也不能替我判断文章值不值得发；不能推出所有模型都如此，更不能推出换模型没有用。判据 2 的强度尤其有限，需要第二个实验交叉验证。
