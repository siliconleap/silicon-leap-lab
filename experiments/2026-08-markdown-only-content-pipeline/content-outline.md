# 内容骨架：纯 Markdown 约定 + Claude Code Skill 的内容流水线

> **回溯重建，未经过实验前确认。** 本文件用于说明新流程本应在开跑前确认什么，不把它伪装成当时已有的计划。

## 已知背景

想把工程、AI 和行业观察沉淀成公开内容，却一直停在比较工具、研究方案和寻找最佳实践的阶段，没有发出一篇文章。需要一个足够小的容器，把「想试的东西」变成可记录、可公开的一次实验。

## 想回答的问题

不依赖 n8n、Coze、Dify、服务器或数据库，只用 Markdown 约定和 Claude Code skill，能否跑出从实验记录到多平台内容初稿的最小流水线？它还缺哪些人工环节？

## 读者与价值

面向想用 agent 沉淀技术内容、但不想先搭一整套内容基础设施的人。读者需要知道：哪些工作可确定性自动化，哪些仍要靠事实核验、编辑判断和平台人工操作。

## 已知困难与边界

- 平台账号、注册认证、预览排版、发布与维护不是本次自动化范围。
- 视频需要录屏、剪辑、配音和字幕，不能假装由纯文本交付。
- 文章结论与个人判断必须由作者确认，不得由初稿替代。
