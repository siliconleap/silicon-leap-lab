# 视频分镜

**实验：** 2026-08-markdown-only-content-pipeline
**形式：** 记录卡 + 数据卡 + 结构图 + TTS 配音 + 字幕，无出镜

> 不写预计时长。时长由配音产生，`build-video.py` 跑完才知道。

## 素材来源

全部画面来自两类一手材料，没有一张示意图，也没有生成 B-roll：

| 来源 | 用途 |
| --- | --- |
| `notes/session-timeline.md` | 11 张记录卡，原话未改写，卡上印时间戳和来源文件 |
| `drafts/*/assets/` | 已有的结构图与对照图 |
| `assets/13-data.html` | 数据卡，数字来自 README Data 与 internal/review*.md |

从 105 条真人输入里选了 13 条。**选的标准是推不推动这条线**，不是有没有信息量——
搭站、配域名、升级工具那些真实发生过，留在 `notes/` 里，不进片。

### S13 · 解法不是换模型

**旁白：**

卡了一周之后，我改的不是模型，是流程：实验前先确认背景和叙事骨架，实验后先写一份短简报，作者确认事实和观点，再展开成各个平台的稿子，最多三轮独立审核。

后来跑了两轮审核，第一轮就抓出十条问题。校验脚本第一次运行，抓到四处死链——之前那是人工 review 才发现的。

耗时和 token 没有记录。这是这次最大的遗憾。

### S15 · 结论

**旁白：**

三条判据，两条成立，一条部分成立。零平台工具做到了，四个平台的初稿也出来了，但初稿达不到能发的水平，过了两轮独立审核才勉强够。

而真正卡住我的不是 AI，是我自己。骨架半天搭完，第一篇拖了一周多，越改越不肯发布。

所以这次学到的是一句话：不苛求完美，不甘愿平庸。苛求完美就永远不发布，甘愿平庸就发了也没人看。路在中间，要靠反复打磨才走得出来。

## 制作备注

- **S15 未定稿，`build-video.py` 会拒绝构建。** 这是有意的——结论没写完就不该出片。
- 中文字幕必做，多数人静音看。
- 不要用转场和音乐掩盖信息不足。
- 记录卡上的原话一个字都不能改。要短就整条换，不要改写。
