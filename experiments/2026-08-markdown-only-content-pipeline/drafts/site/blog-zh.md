研究报告和前沿资讯读了很多。看到一个方向，也常常觉得值得做。

真正动手的尝试却很少。回头看，这是一种眼高手低：输入越来越多，行动没有形成闭环；想做的事越积越多，最基础的「开始、记录、整理、公开」反而没走顺。

我怀疑这不只发生在 AI 领域。想学一门技能、做个项目或者改掉一个习惯，大概也会卡在同一处：知道得更多，第一步却迟迟没有开始。这是我自己的观察，不是调研结论。

我本来以为，AI 时代至少能让这几步变简单。于是换了个办法：给「想试的东西」找一个容器。每件事都当成一次实验——一个目录，一份记录，一次公开。

第一个实验就是用 AI 把这套记录机制本身做出来。

半天搭完的是流水线骨架。第一篇内容却让我拖了一周多，还是不愿意发。

不是代码卡住了。初稿看起来完整，读起来却没有一句让我想留下来。我越不满意，越继续改流程和文案，也越不肯开始发布——差点又回到最初「研究很多、没有真正开始」的状态。

## 这套东西是什么

两个仓库，全是纯文本：

| 仓库 | 角色 |
| --- | --- |
| `silicon-leap-forge` | 流水线本体：skill、平台配置、模板、约定文档 |
| `silicon-leap-lab` | 实验记录，流水线的输入和输出都在这里 |

两个 skill：`experiment-plan` 把一句话选题变成能照着跑的实验目录；`content-forge` 把跑完的实验变成各平台初稿。环境是 macOS 加 Claude Code CLI 加 git，没装别的东西。

要验证的问题：只靠 Markdown 约定加 skill，不用 n8n、Coze、Dify，不用服务器和数据库，这条流水线能不能真跑起来。

答案是能。但这是整个实验里最不重要的结论。

## 完整的外观，空的内容

生成出来的 skill 有 frontmatter，有分步流程，有硬约束清单，还有验收标准。该有的都有，读起来像个成熟的东西。

我批准它只花了一句话：「可以，写出来。」

直到我让它真的跑一遍。

产出的第一篇小红书文案，枯燥得读不下去。不是写错了，是没法看。

![配置与模板的实际内容对照](../wechat/assets/01-contradiction.png)
*图 1：配置与模板的实际内容对照，来源为本次实验的两个文件*

翻开模板才看见根子。里面硬编码了一套骨架：「结果」「有效的」「踩的坑」，三段列表。

而在同一套配置的另一个文件里，写着这么一句：

> 陈述完事实就转进列表。没有处境，没有反应，数字没有参照系。

配置在骂模板，模板在违反配置。

最麻烦的地方在于：两个文件分开看，每一个都是对的。矛盾只在真跑一遍、读到产出的那一刻才出现。

## 一条从没能执行的规则

再往下翻，配图那一节写着：输出 SVG 源文件，由人渲染。

我查了这台机器。rsvg-convert、ImageMagick、wkhtmltoimage，一个都没装。

这条规则从写下的那天起就没有执行的可能。它读起来合理，也符合「纯文本、可版本控制」的目标，唯独没人确认过这台机器上有没有渲染器。

## 这次能说明什么，不能说明什么

这是一次实验，不足以证明所有模型都会写得平淡，也不能推出换模型没有用。

它只证明了两件具体的事：这次生成没有发现两个本地文件互相矛盾；它也无法替我判断一篇文案是否值得发。

所以把打磨放进流程，别把初稿当成品。初稿先过一轮独立审核，看事实、结论边界、逻辑、可读性和平台适配；最多改三轮，仍不达标就标成「不可发布」。

## 拿到了什么

回过头把要求逐条写进 skill：

- 反 AI 腔负面清单，七类。套路化小标题、benefit 列表、空泛 buzzword、作文骨架、没数据撑的程度词、万能收尾、连用的排比句
- 叙事必须讲全四件事：为什么选这个实验、中间哪些失败、成果是什么、能否复制
- 中文行文规则：句子短，主语在前，少用「被」，删掉「进行了」「实现了」这类壳子
- 模板从三段列表改回叙事结构
- 配图必须真的渲染出来，不能只写「配图说明」

![三层职责划分](../wechat/assets/02-layers.png)
*图 2：三层职责划分，来源为本次实验的 Artifacts 段*

更管用的是把确定性的部分沉进脚本。目录骨架、七段标题、校验、配图渲染，这些不需要判断，交给 shell 脚本。剩下要判断的才归 agent，也就是 Claude Code 里那套帮我写初稿、跑固定检查的工作流，最后真正要拍板的才归人。

校验脚本写完第一次跑就抓出四处死链，此前这类问题得人工 review 才看得见。

配图链路最后落在 HTML 渲染成 PNG，用系统自带的 Chrome，零额外安装。HTML 进 git、可 diff，PNG 是产物。

## 哪些能复制，哪些不能

这次的做法是把确定性沉进脚本，把「不要什么」写进指令。换模型、换题目、换渠道还成不成立，得另外验证。

不能复制的是这次的具体产物。平台配置照着这几个渠道写的，换个渠道要重写。

视频这一路先被判成死路，后来发现判错了。当时的理由是录屏为 0，剪辑、配音、字幕都没有自动化路径。真正缺的只是一手画面素材，而组装是确定性的：分镜写成纯文本，配音走 TTS，画面按配音时长铺开再拼，字幕直接用旁白。第一条成片 4 分 24 秒，1920×1080，60 条字幕，画面全是会话记录卡、结构图和数据卡，没有录屏也没有示意图。当时把「缺画面素材」和「缺组装工序」混成了一件事。

## 需要说明的地方

这份记录是回溯补写的。`plan.md` 本该在开跑前写，实际是事后还原，所以「预期反直觉点」那一节只能删掉换成「实际发现」——事后补的预测没有价值。

耗时和 token 全程没记录，而且 `--reset-author` 重置了 commit 时间戳，git 历史也当不了耗时依据。

没有录屏：asciinema 从未装过，更根本的是工作方式变了——人跟 agent 对话，agent 执行，终端里没有「人的操作过程」可录。真正的过程记录是对话本身，这次是事后才从会话记录里把它捞出来的，共 105 条真人输入，8/08 到 8/18 全程带时间戳。

`validate.sh` 抓出四处死链的原始终端输出也已被覆盖。文中的结构图只能说明流程，不能替代那次现场；以后补拍必须明确标为「复现」。

平台工具依赖为 0，不等于发布成本为 0。账号注册与维护、补真实截图、作者确认、手机预览、排版、发布和评论维护都仍是人工动作；这份内容包没有执行或验证这些动作。

## 结论

三条判据都成立，但没有一条是全自动成立的。前段能从一句话选题产出可照着跑的实验目录，后段几个平台的内容包也确实各不相同，全程零平台工具。但中间的判断全是人做的：哪个缺口值得补、初稿为什么读不下去、哪句原话该留、结论能说到哪里。这套东西不是省掉人，是把人从确定性的活里换出来。

AI 干活快，但普通的提示词只会换来平庸的结果。平庸不是模型的属性，是默认值：没有明确约束时，生成自然回归均值，而均值就是平庸。换个更大的模型只会得到一个更精致的均值。真正起作用的是把「抗拒平庸」写进指令本身，逐条写清不要什么、为什么不要。打磨的地方不在产物上，在指令上。

真正卡住我的不是 AI，是我自己。骨架半天搭完，第一篇却拖了一周多。所以这次学到的是一句话：不苛求完美，不甘愿平庸。两头都是失败，苛求完美就永远不发布，甘愿平庸就发了也没人看。

边界：样本量为 1。这次只能说明该生成过程没有自行发现跨文件矛盾，也不能替我判断文章值不值得发；不能推出所有模型都如此，更不能推出换模型没有用。
