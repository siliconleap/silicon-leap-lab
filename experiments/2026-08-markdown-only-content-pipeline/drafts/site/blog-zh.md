收藏夹里躺着一千篇「以后要做」，换不来一次真正的成长。成长发生在做完一件事的时候，不是读完第一千零一篇的时候。

这次我用 AI 搭了一条内容流水线，再用它记录这次实验本身。骨架半天就搭完了，第一篇内容却卡了一周多。

卡住的不是代码。AI 干活快，但普通的提示词只会换来平庸的结果——平庸不是模型的属性，是默认值：没有明确约束时，生成自然回归均值，而均值就是平庸。要拿到均值以上的东西，只能把「不要什么、为什么不要」逐条写进指令，而这件事只有人能做。

这套东西不省人，它把人从确定性的活里换出来。剩下那些判断，正好是收藏一千篇换不来的部分。

下面是这一周多具体发生了什么。

## 起点：一个容器

真正动手的尝试很少。回头看，这是一种眼高手低：输入越来越多，行动没有形成闭环；想做的事越积越多，最基础的「开始、记录、整理、公开」反而没走顺。

我怀疑这不只发生在 AI 领域，虽然这只是我的观察，没有数据。想学一门技能、做个项目、改掉一个习惯，大概也卡在同一处：知道得更多，第一步却迟迟没有开始。

我本来以为，AI 时代至少能让这几步变简单。于是换了个办法：给「想试的东西」找一个容器。每件事都当成一次实验——一个目录，一份记录，一次公开。第一个实验就是用 AI 把这套记录机制本身做出来。

初稿看起来完整，读起来却没有一句让我想留下来。我越不满意，越继续改流程和文案，也越不肯开始发布——差点又回到最初「研究很多、没有真正开始」的状态。

## 这套东西是什么

两个仓库，全是纯文本：

| 仓库 | 角色 |
| --- | --- |
| `silicon-leap-forge` | 流水线本体：skill、平台配置、模板、约定文档 |
| `silicon-leap-lab` | 实验记录，流水线的输入和输出都在这里 |

两个 skill：`experiment-plan` 把一句话选题变成能照着跑的实验目录；`content-forge` 把跑完的实验变成各平台初稿。环境是 macOS 加 Claude Code CLI 加 git，没装别的东西。

要验证的问题：只靠 Markdown 约定加 skill，不用 n8n、Coze、Dify，不用服务器和数据库，这条流水线能不能真跑起来。

答案是能。但这是整个实验里最不重要的结论。

## 完整的外观，空的内容

生成出来的 skill 有 frontmatter，有分步流程，有硬约束清单，还有验收标准。该有的都有，读起来像个成熟的东西。

我批准它只花了一句话：

> 可以，写出来，后续软链我想办法建

（[`notes/session-timeline.md`](https://github.com/siliconleap/silicon-leap-lab/blob/master/experiments/2026-08-markdown-only-content-pipeline/notes/session-timeline.md)，2026-08-09 07:11:50）

直到我让它真的跑一遍。

产出的第一篇小红书文案，枯燥得读不下去。不是写错了，是没法看。

![配置与模板的实际内容对照](../wechat/assets/01-contradiction.png)
*图 1：配置与模板的实际内容对照，来源为本次实验的两个文件*

翻开模板才看见根子。里面硬编码了一套骨架：「结果」「有效的」「踩的坑」，三段列表。

而在同一套配置的另一个文件里（`platforms/xiaohongshu.md`），写着这么一句：

> 陈述完事实就转进列表。没有处境，没有反应，数字没有参照系。

配置在骂模板，模板在违反配置。

最麻烦的地方在于：两个文件分开看，每一个都是对的。矛盾只在真跑一遍、读到产出的那一刻才出现。

## 一条从没能执行的规则

再往下翻，配图那一节写着：输出 SVG 源文件，由人渲染。

我查了这台机器。rsvg-convert、ImageMagick、wkhtmltoimage，一个都没装。

这条规则从写下的那天起就没有执行的可能。它读起来合理，也符合「纯文本、可版本控制」的目标，唯独没人确认过这台机器上有没有渲染器。

## 这次能说明什么，不能说明什么

这是一次实验，不足以证明所有模型都会写得平淡，也不能推出换模型没有用。

它只证明了两件具体的事：这次生成没有发现两个本地文件互相矛盾；它也无法替我判断一篇文案是否值得发。

还有一件是我自己的问题。跑到中段我在会话里写下这句：

> 生成了代码和 skill 之后，我压根没有理解内部的逻辑

（[`notes/session-timeline.md`](https://github.com/siliconleap/silicon-leap-lab/blob/master/experiments/2026-08-markdown-only-content-pipeline/notes/session-timeline.md)，2026-08-10 14:54:07，措辞经过整理，原话更长）

所以把打磨放进流程，别把初稿当成品。初稿先过一轮独立审核，看事实、结论边界、逻辑、可读性和平台适配；一批稿子最多改三轮，仍不达标就标成「不可发布」。三轮是表达层的上限，事实、标题或结构被推翻就算新一批、重新计轮——这篇到发出来一共跑了六轮。

## 拿到了什么

回过头把要求逐条写进 skill：

- 反 AI 腔负面清单，七类。套路化小标题、benefit 列表、空泛 buzzword、作文骨架、没数据撑的程度词、万能收尾、连用的排比句
- 叙事必须讲全四件事：为什么选这个实验、中间哪些失败、成果是什么、能否复制
- 中文行文规则：句子短，主语在前，少用「被」，删掉「进行了」「实现了」这类壳子
- 模板从三段列表改回叙事结构
- 配图必须真的渲染出来，不能只写「配图说明」

![三层职责划分](../wechat/assets/02-layers.png)
*图 2：三层职责划分，来源为本次实验的 Artifacts 段*

更管用的是把确定性的部分沉进脚本。目录骨架、七段标题、校验、配图渲染，这些不需要判断，交给 shell 脚本。剩下要判断的才归 agent（Claude Code 里那套帮我写初稿、跑固定检查的工作流），最后真正要拍板的才归人。

校验脚本写完第一次跑就抓出四处死链，此前这类问题得人工 review 才看得见。

配图链路最后落在 HTML 渲染成 PNG，用系统自带的 Chrome，零额外安装。HTML 进 git、可 diff，PNG 是产物。

## 哪些能复制，哪些不能

这次的做法是把确定性沉进脚本，把「不要什么」写进指令。换模型、换题目、换渠道还成不成立，得另外验证。

不能复制的是这次的具体产物。平台配置照着这几个渠道写的，换个渠道要重写。

还有一处彻底失败：视频渠道交付不了。脚本、标题、封面方案都能生成，因为它们是纯文本。组装那一段也试通了：分镜写成纯文本，配音走 TTS，画面按配音时长铺开再拼，字幕直接用旁白，跑出过一版 4 分 24 秒的东西。但它达不到能发的标准——录屏为 0，画面只能拿会话记录卡和结构图凑，没有一帧是真实现场。纯文本这套办法在前几个渠道成立，到视频这里失效了。门槛比想象的高。

## 需要说明的地方

这份记录是回溯补写的。`plan.md` 本该在开跑前写，实际是事后还原，所以「预期反直觉点」那一节只能删掉换成「实际发现」——事后补的预测没有价值。

耗时和 token 全程没记录，而且 `--reset-author` 重置了 commit 时间戳，git 历史也当不了耗时依据。

没有录屏：asciinema 从未装过，更根本的是工作方式变了——人跟 agent 对话，agent 执行，终端里没有「人的操作过程」可录。真正的过程记录是对话本身，这次是事后才从会话记录里把它捞出来的，共 105 条真人输入，8/08 到 8/18 全程带时间戳。

`validate.sh` 抓出四处死链，那次运行的输出没有留下来。补拍也没有意义：我压根没打开过终端，命令是 agent 执行的，所谓「终端现场」在这种工作方式里根本不存在。这类证据的真身是会话记录和 git 提交，不是截图。

平台工具依赖为 0，不等于发布成本为 0。账号注册与维护、补真实截图、作者确认、手机预览、排版、发布和评论维护都仍是人工动作；这份内容包没有执行或验证这些动作。

## 这次结论的边界

先把判据结掉：三条都成立，但没有一条是全自动成立的。前段能从一句话选题产出可照着跑的实验目录，后段几个平台的内容包确实各不相同，全程零平台工具。中间那些判断全是人做的——哪个缺口值得补、哪句原话该留、结论能说到哪里。

样本量为 1。能说的只有：这一次的生成没有自行发现两个本地文件互相矛盾，也没能替我判断一篇文案值不值得发。推不到「所有模型都这样」，更推不出「换模型没有用」。判据 2 的强度尤其有限，要等第二个实验交叉验证。

方法层面能带走多少也得算清楚。跨题目大概还成立的是两条：理解成本不会消失，只会后置，批准时省下的追问，用起来连本带利还回来；确定性沉进脚本之后，人要理解的表面积才会缩小。平台配置是照着这几个渠道写死的，换渠道等于重写。

两处硬缺口留在这里，不打算粉饰：视频到现在没做出能发的东西；耗时和 token 全程没记，这次的「一周多」是事后回忆，不是测量。

还有一处不算缺口，但值得说：这次没有一张终端截图，也不该有。命令都是 agent 执行的，人从头到尾在对话框里。按老习惯我会把「没有终端截图」记成短板，实际上是证据形式换了——一手材料是会话记录和 git 历史。用旧形态的标准审新形态的工作，会一直扣一个补不上的分。

下一个实验带着 `plan.md` 先跑，不再事后补。有了开跑前的预测，猜错的地方才能当下一篇的开头。

至于我自己，这次学到的是一句话：不苛求完美，不甘愿平庸。苛求完美就永远不发布，甘愿平庸就发了也没人看。
