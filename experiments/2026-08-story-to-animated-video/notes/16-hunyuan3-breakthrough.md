# 混元生图 3.0 支持参考图，整场用错了模型

**日期：** 2026-08-25
**起因：** 作者指出「腾讯不吃参考图」不该被当成既定限制绕过去，而是该专门解决，并且相信它可解。
**结论：作者是对的，我错了两次。**

## 我错在哪

我在 `notes/01b-capabilities.md` 和困难清单第 7 条里写下的结论是：腾讯 aiart 不接受参考图，
所以角色一致性只能靠文字锚点，而姿态根本控制不了。

**实测过的只有两个接口：**

- `TextToImageLite`——文生图，本来就不收图
- `ImageToImage`——风格迁移，测出它不能换姿态

**没测过的：** 混元生图 2.0、3.0、图像编辑、线稿生图。整整一排。

而且 `TextToImageLite` 的名字里就写着 **Lite**。**我们整场用的是轻量版模型**，姿态执行不了
很可能从来就不是「不吃参考图」的问题，是模型能力的问题。

## 实际情况

`SubmitTextToImageJob`（混元生图 3.0），**同一个端点 `aiart.tencentcloudapi.com`、同一个
Version `2022-12-29`、同一套凭据**：

| 参数 | 说明 |
| --- | --- |
| `Images.N` | **参考图，最多三张**，base64 或 URL |
| `Prompt` | 最长 8192 字符 |
| `Seed` | 1–4294967295 |
| `LogoAdd` | 同 Lite |
| `Revise` | 提示词改写开关，默认开 |

异步：`SubmitTextToImageJob` 拿 `JobId`，`QueryTextToImageJob` 轮询，`JobStatusCode` 为 5 时
在 `ResultImage` 里取 URL。单张约 10 秒。

**「最多三张参考图」这个数量，正好对上那篇文章说的三视图 + 细节笔触图 + 场景图。**

## 用当初失败的姿态重测

拿 `fox-sit.png` 当参考图，原样再跑一遍在 Lite 上 0/8 命中的三个姿态
（`notes/probe/hy-cmp.png`，左起：参考图 / 回头看 / 抬前爪 / 仰躺）：

| 姿态 | Lite | 3.0 带参考图 |
| --- | --- | --- |
| 抬起一只前爪悬空 | ✗ 四蹄着地 | **✓ 前爪抬起来了** |
| 四脚朝天仰躺，白肚皮朝上 | ✗ 侧卧 | **✓ 四腿举在空中，肚皮朝天** |
| 头扭向右后方回头看 | ✗ 正常侧走 | △ 头转了但幅度不足 |

**仰躺那张尤其关键**——当初就是因为它做不出来，才被迫用「侧视图旋转 180 度」假装翻身，
结果尾巴翘着，被作者一眼看出很奇怪；后来又绕了一圈用俯视角度才勉强解决。

其余两处同样被推翻：

- **纯白背景**：Lite 每次都无视这条指令、自带地面和天空；3.0 给的是真的纯白背景
- **画质**：3.0 有真实的纸张纤维、撕边毛口和层次；Lite 是平涂色块（对比见 `notes/probe/hy-bg.png`）

## 限制

`Resolution` 受面积约束（每边 512–2048，且面积不超过 1024×1024）。实测：

| 分辨率 | 结果 |
| --- | --- |
| 1920:1080 | ✗ 拒绝 |
| 1536:864 | ✗ 拒绝 |
| **1365:768** | ✓ 接受 |
| **1280:720** | ✓ 接受 |

所以 16:9 最大只能到 1365×768，进 1920×1080 的合成要放大约 1.4 倍。对纸质纹理这种内容
可以接受，但不是无损。

## 这条推翻了什么

**困难清单第 7 条的结论要改。** 原来写的是「姿态控制不是提示词写法问题，是模型对物体概念的
先验太强」——**不成立**。真相是「Lite 模型控制不了姿态，而同产品下的 3.0 带参考图可以」。

由此连带的两处也要重新表述：

1. **「生成端给不了的，编排端可以给」（第 11 条）仍然成立，但它不再是被迫的。** 当时是因为
   姿态做不出来才把动作全交给代码；现在两条路都能走，代码编排是选择不是退路。
2. **「这套能力对故事类型挑食」（第 13 条）需要复核。** 当时判断片 A 比片 B 顺，理由之一是
   「道具没有身份不会漂移，也不需要姿态」——而姿态短板若不存在，这个理由就弱了一半。

## 为什么值得单独记

这是我在这次实验里**第四次**在没测全的情况下下限制性结论：

1. 信官方文档不信仓库里的一手水印记录
2. 没读原文就断言角色一致性方案靠不住
3. 把「姿态生成不出来」这个阶段性结论扩大成普遍限制
4. 这一次：只测了一个产品线里最轻量的那个接口，就断言整个产品不支持参考图

**四次的共同点是一样的：拿一个局部观察替代对整个空间的检查。**而这一次的代价最大——
它不是让某一拍不好看，而是**让整条技术路线的设计围绕一个不存在的限制展开**：分镜怎么写、
故事怎么选、动作交给谁，全都为了绕开它。

作者的原话是：「如果因为这个问题而对最终的方案做了各种取舍，那么就需要专门解决一下。
同时我相信这个问题应该是可以解决的。」——**这是判断该不该接受一个限制的正确姿势，而我
四次都是先接受再绕路。**
