# 混元生图 3.0 支持参考图，整场用错了模型

**日期：** 2026-08-25
**起因：** 作者指出「腾讯不吃参考图」不该被当成既定限制绕过去，而是该专门解决，并且相信它可解。
**结论：作者是对的，我错了两次。**

## 我错在哪

我在 `notes/01b-capabilities.md` 和困难清单第 7 条里写下的结论是：腾讯 aiart 不接受参考图，
所以角色一致性只能靠文字锚点，而姿态根本控制不了。

**实测过的只有两个接口：**

- `TextToImageLite`——文生图，本来就不收图
- `ImageToImage`——风格迁移，测出它不能换姿态

**没测过的：** 混元生图 2.0、3.0、图像编辑、线稿生图。整整一排。

而且 `TextToImageLite` 的名字里就写着 **Lite**。**我们整场用的是轻量版模型**，姿态执行不了
很可能从来就不是「不吃参考图」的问题，是模型能力的问题。

## 实际情况

`SubmitTextToImageJob`（混元生图 3.0），**同一个端点 `aiart.tencentcloudapi.com`、同一个
Version `2022-12-29`、同一套凭据**：

| 参数 | 说明 |
| --- | --- |
| `Images.N` | **参考图，最多三张**，base64 或 URL |
| `Prompt` | 最长 8192 字符 |
| `Seed` | 1–4294967295 |
| `LogoAdd` | 同 Lite |
| `Revise` | 提示词改写开关，默认开 |

异步：`SubmitTextToImageJob` 拿 `JobId`，`QueryTextToImageJob` 轮询，`JobStatusCode` 为 5 时
在 `ResultImage` 里取 URL。单张约 10 秒。

**「最多三张参考图」这个数量，正好对上那篇文章说的三视图 + 细节笔触图 + 场景图。**

## 用当初失败的姿态重测

拿 `fox-sit.png` 当参考图，原样再跑一遍在 Lite 上 0/8 命中的三个姿态
（`notes/probe/hy-cmp.png`，左起：参考图 / 回头看 / 抬前爪 / 仰躺）：

| 姿态 | Lite | 3.0 带参考图 |
| --- | --- | --- |
| 抬起一只前爪悬空 | ✗ 四蹄着地 | **✓ 前爪抬起来了** |
| 四脚朝天仰躺，白肚皮朝上 | ✗ 侧卧 | **✓ 四腿举在空中，肚皮朝天** |
| 头扭向右后方回头看 | ✗ 正常侧走 | △ 头转了但幅度不足 |

**仰躺那张尤其关键**——当初就是因为它做不出来，才被迫用「侧视图旋转 180 度」假装翻身，
结果尾巴翘着，被作者一眼看出很奇怪；后来又绕了一圈用俯视角度才勉强解决。

其余两处同样被推翻：

- **纯白背景**：Lite 每次都无视这条指令、自带地面和天空；3.0 给的是真的纯白背景
- **画质**：3.0 有真实的纸张纤维、撕边毛口和层次；Lite 是平涂色块（对比见 `notes/probe/hy-bg.png`）

## 限制

`Resolution` 受面积约束（每边 512–2048，且面积不超过 1024×1024）。实测：

| 分辨率 | 结果 |
| --- | --- |
| 1920:1080 | ✗ 拒绝 |
| 1536:864 | ✗ 拒绝 |
| **1365:768** | ✓ 接受 |
| **1280:720** | ✓ 接受 |

所以 16:9 最大只能到 1365×768，进 1920×1080 的合成要放大约 1.4 倍。对纸质纹理这种内容
可以接受，但不是无损。

## 这条推翻了什么

**困难清单第 7 条的结论要改。** 原来写的是「姿态控制不是提示词写法问题，是模型对物体概念的
先验太强」——**不成立**。真相是「Lite 模型控制不了姿态，而同产品下的 3.0 带参考图可以」。

由此连带的两处也要重新表述：

1. **「生成端给不了的，编排端可以给」（第 11 条）仍然成立，但它不再是被迫的。** 当时是因为
   姿态做不出来才把动作全交给代码；现在两条路都能走，代码编排是选择不是退路。
2. **「这套能力对故事类型挑食」（第 13 条）需要复核。** 当时判断片 A 比片 B 顺，理由之一是
   「道具没有身份不会漂移，也不需要姿态」——而姿态短板若不存在，这个理由就弱了一半。

## 为什么值得单独记

这是我在这次实验里**第四次**在没测全的情况下下限制性结论：

1. 信官方文档不信仓库里的一手水印记录
2. 没读原文就断言角色一致性方案靠不住
3. 把「姿态生成不出来」这个阶段性结论扩大成普遍限制
4. 这一次：只测了一个产品线里最轻量的那个接口，就断言整个产品不支持参考图

**四次的共同点是一样的：拿一个局部观察替代对整个空间的检查。**而这一次的代价最大——
它不是让某一拍不好看，而是**让整条技术路线的设计围绕一个不存在的限制展开**：分镜怎么写、
故事怎么选、动作交给谁，全都为了绕开它。

作者的原话是：「如果因为这个问题而对最终的方案做了各种取舍，那么就需要专门解决一下。
同时我相信这个问题应该是可以解决的。」——**这是判断该不该接受一个限制的正确姿势，而我
四次都是先接受再绕路。**

# 用 3.0 重做片 A

**日期：** 2026-08-25
**范围：** 只重做片 A。作者的判断是片 B 只是 demo，「我只是想知道用这套方案能不能生成任意一个动画故事，现在看来是可以的」。

## 作者给的参照

一张千手观音工笔画（`notes/probe/case193.png`），千手拿的不是法器，是笔记本、智能手机、
成堆的文件、咖啡杯、印章、计算器、拖把和奶瓶；脑后光环由旋转的时钟齿轮组成；右下角一枚
红色竖排印章。

**对着它拆我们的 prompt，问题一眼可见。** 片 A 原来的道具 prompt 是这样的：

```
剪纸拼贴风格插画，纸张纤维质感，可见纸张毛边和轻微投影，黑色细描边，扁平构图，
不要文字；统一色板：米白纸底、暖褐色木质、靛蓝色、橙红色点缀、深灰；
一个靛蓝色的齿轮，纸片层叠而成，主体完整居中，画面很大占满，纯白色背景
```

**九成在描述材质和约束，只有「一个靛蓝色的齿轮」这七个字在说画面里有什么。**
一个齿轮孤零零放在白底上，它不可能精美——里面什么都没有。换更强的模型只会把这份空洞
渲染得更清晰。

## 拆出来的五段结构

| 段 | 那张观音图 | 我们原来的 |
| --- | --- | --- |
| 具体画种/技法 | 工笔画 | 「剪纸拼贴风格插画」（不是一个技法名） |
| 有张力的核心概念 | 千手拿的是奶瓶和拖把 | 无 |
| 可数的物件清单 | 八类，填满画面 | 一件 |
| 次级细节层 | 光环是时钟齿轮、待办清单、牡丹、云纹 | 无 |
| 角落细节 | 右下红色竖排印章 | 无 |

这一节已经提升进 `editorial-video/references/prompt-standard.md`。

## 重写后的样子

第一张试的是书桌（`notes/probe/rich-desk.png`）：三叠稿子越往右改动越少、橙红批改痕迹、
便签、钢笔、裁纸刀、橡皮、笔筒、见底的咖啡杯和干掉的咖啡渍、摘下的眼镜、合上的笔记本、
从左上打来的光、拉向右下的影子、右下角一枚红印。

**一次成功，7 秒。** 同一个模型，只是 prompt 里真的有内容了。

## 产出

- **4 张背景**（`bg1-shelf` / `bg2-desk` / `bg3-paper` / `bg4-night`），互相之间用第一张当
  参考图，保证是同一个世界：红印、光向、撕边全部一致
- **11 件道具**，纯白背景单件，抠图全部干净——**Lite 从来做不到真正的纯白背景**
- 钟的表盘中心被分割当成背景抠掉了，补了一层米白纸表盘＋指针合成的 `p-clock-face`，
  圆盘旋转对称，转起来只看得见指针动
- 背景里已经画了台灯，原来那层 `lamp-desk` 因此删掉

## 一个有意的风格漂移

3.0 把「剪纸拼贴」渲染成了**纸艺立体摄影**——多层手工纸叠出真实景深和投影，而不是扁平色块。
**接受这个漂移**：作者要的是精细，而扁平剪纸的细节天花板就在那里。片 B 保持原样，两支片子
因此风格不同——它们本来就是两个片子，B 是 demo。

## 结果

| 指标 | Lite 版 | 3.0 版 |
| --- | --- | --- |
| 审计得分 | 100 | 100 |
| 最长静止画面 | 2.75 秒 | **0.75 秒** |
| 时长 | 178.53 秒 | 178.53 秒 |
| 体积（CRF 23） | 57 MB | 65 MB |
| 图像调用 | 16 次（Lite） | 15 次（3.0） |
| 单张耗时 | 约 6 秒 | 约 7–10 秒 |

最长静止画面从 2.75 秒降到 0.75 秒，不是因为改了关键帧——**是因为新素材本身有纹理和层次，
连轻微的位移都会在画面上产生可见变化**。扁平色块平移时，很大一片区域的像素根本不变。
