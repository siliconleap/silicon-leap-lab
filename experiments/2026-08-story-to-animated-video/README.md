# AI 能不能把一个故事讲成一支能发的动画视频？

## Question

给一段文字讲的故事——没有分镜、没有素材、没有录像——AI 能不能自己把它变成一支画面连贯、能发出去的动画视频？

## Setup

**环境**

- macOS，Claude Code CLI，模型 Opus 5，Node v24.6.0
- 图像：腾讯云 aiart `TextToImageLite`（`ap-guangzhou`），密钥取自 `TENCENTCLOUD_SECRET_ID` / `_KEY`
- 配音：腾讯云 TTS，音色 501000，`Speed=0`
- 渲染：Remotion（首选候选的默认渲染器，本机尚未安装依赖）
- 无 OpenAI API key，无图形编辑软件，无实拍设备

**被测对象**

首选候选是 `~/Code/editorial-video`（skill 名 `illustrated-videos`）的分层插画视频流水线：每个 scene 拆成不含主体的背景板，加若干独立生成的带 alpha 的主体、道具与前景层，再由 Remotion 合成、加语义动效与字幕。

但它不是前提。步骤 1 先横向调研开源的 story → video 路线，按技术形态分类——素材拼接型（脚本 + 库存素材 + TTS，适合口播和资讯流）、文生视频扩散模型（适合电影质感的短片）、代码合成型（Remotion 这类，适合可控的插画讲解）——判断哪一类匹配本次要的「插画动画」，再从中挑一条装起来实测，A、B 两支片子共用它。没被选中的路线不代表不好，很可能只是适合别的场景，调研结论里要写清楚。调研是分析层面的，不逐个安装。

**任务**

两支片子，同一条流水线，故事类型故意拉开距离。

| 片 | 故事来源 | 为什么选它 |
| --- | --- | --- |
| A | 实验 `2026-08-markdown-only-content-pipeline` 的全过程记录 | 有真实截图和结构图可用，硬信息密集，且能补上那次缺的第四个渠道 |
| B | 一则公有领域童话 | 纯文字输入，零素材，无技术门槛，画面全靠生成 |

A 的素材来源是那个实验目录的全部记录：`README.md` 七段、`notes/session-timeline.md` 的 105 条真人输入、`drafts/youtube/scenes.md` 的 13 个 scene、`internal/review1-6.md`。目录里已有的真实截图与结构图可以进片；没有截图可用的段落，必须由生成的分层插画承担，不许用文字卡片充数。

B 不提供任何图，全部画面生成。

两支都跑完才算完，因为这次要验的不是「能不能讲好那个实验」，是**这套生成能力对故事本身有多挑食**。A 成 B 不成，说明它依赖现成素材；A 不成 B 成，说明它讲不了信息密集的内容；都成，才谈得上通用。

**形式约束**

- 画幅 16:9，1920×1080，两支一致（理由见 `plan.md` 的画幅一节）
- 非口播：不出镜，不用真人画面，旁白只走 TTS
- 全程由 AI 执行，人只做审核和局部微调，每次干预逐条记进 `data/interventions.md`

**判据**

1. 两支片子都在 180 秒以内，且都通过所选流水线自带的 QA
2. 两支里都没有单张静止画面连续超过 8 秒——这是上一支片子被判不合格的直接病根
3. 同一条流水线跑两种故事，人工干预次数各是多少、差在哪。差得越小，通用性越强

**已知短板**

作者无美术、动画、策划、编辑背景，对「精美」的判断只能是主观打分，不构成客观判据。平台账号尚未注册，本次拿不到发布后的真实数据。

## Log

起点是上一个实验留下的一个洞。四个渠道做完三个，视频那一栏写着「失败」——不是没试，是试出一支 4 分 24 秒的成片之后判定不能发。理由很具体：画面是一堆截图的简单拼接，算不上动画，非常不连贯。那次的 README 因此写死了一句「视频不是纯文本，也没法由纯文本生成」。

这次回来推翻它，而且推得更远一点：不只补那个渠道，而是验证「给一段文字讲的故事，AI 能不能自己把它变成动画」。两支片子，故事类型故意拉开——一支讲上一个实验的过程，一支讲一则原创童话。

**第一步是横向调研，不预设用哪条路线。** 十个项目，star 数和最后推送日期全部从 GitHub API 实时拉取。最有用的一列是最后推送日期：ShortGPT 停在 2025-02，StoryDiffusion 停在 2024-09。四类路线里选了代码合成型，理由是判据 2 直接指着它——「没有静止画面超过 8 秒」本质上是要求画面里有编排好的变化，而只有代码能把变化写死并复现。

**第二步是把好的做法整合进选定的那条流水线，结果规模比预想小。** 上一个实验留下的时间轴教训——旁白按句合成、每句时长取自合成端、裁掉头尾静音再按标点补回停顿——读源码发现已经整个在 `editorial-video` 里了。真正的缺口在别处：`preflight.mjs` 的三个 provider 白名单里没有腾讯云的生图和 TTS，而实现代码在、文档也写了整整一节。**这台机器上唯一有密钥、唯一跑得起来的组合，校验器会直接拒绝。**

这是上一个实验那个招牌发现的第二次出现，形状一样：脚本支持、文档写了、校验不认，三个文件分开看每一个都对。同一个 bug 后来又出现了第三次——`validate-manifest.mjs` 有自己独立的一份白名单，项目通过了 preflight、跑完全部素材生成和抠图，走到清单校验才被拒。**失败点越靠后，浪费越多。**

**水印那件事绕了四轮。** 仓库里 `providers.md` 写着「`LogoAdd: 0` 去不掉『AI 生成』标，已目视核实」，代码注释写着相反的。作者说网上查到能关，要求核实。我查了腾讯官方文档，三个接口口径一致支持「能关」，于是判定那份一手记录错了并改写了它。实测：传 0 和传 1 生成的两张图右下角一模一样，**一手记录是对的，文档是错的，我改错了**。改回之后，作者去后台打开了一个配置开关，重测——`LogoAdd` 完全按文档行为。完整机制是：参数是真的，但被一个账号级的后台设置 gate 住，而响应里没有任何字段能区分这两种状态。**三方各错一半：文档漏了 gate，一手记录把自己账号的状态当成了系统属性，我漏了实测。**

**角色一致性是第二次判断反了。** 我写下「prompt anchor 加人工检查，本质上是用文字反复约束，靠不住」，并据此建议引入外部厂商。作者说：我记得 editorial-video 里有处理的。回去读原文，是一套四层机制——结构化锚点格式、稳定部分逐字重复、姿态成组审而非逐张过、漂移只能重生成不许用快转场遮掩。实测六张图，两组都保持住了同一只狐狸。**「靠不住」是没测就下的判断。**

**但真正的短板在姿态。** 按锚点写了 8 个姿态，身份八张如出一辙，姿态基本没有被执行——要「回头看」给正常侧走，要「前蹄抬起悬空」给四蹄着地。挑最差的四个重生成，姿态提到最前、加负向提示词，四个里只好了一个，**而且身份漂了**：强调姿态就必须改写那些本该逐字重复的部分，两个目标在同一段文本里互相挤。

这一下把整条路线的打法改了：**不再指望用不同的图表达不同的动作，动作全部交给 `motion.keyframes`。** 后来那朵「一整片巨大的雪花」也是同样的解法——图错了没重新生成，在分镜里当成单片雪花用了 17 次。**生成端给不了的，编排端往往可以给。**

**两支片子的结果和开跑前的预测相反。** 预期是童话更适合插画、软件实验会更别扭。实际是片 A 更顺：重渲 2 次对 4 次，最长静止画面 2.00 秒对 4.00 秒。原因有两条——A 有四张一手产物承担了最难画的四拍，B 什么都得生成；以及 A 根本不需要角色，抽象概念用道具就能演，**而道具没有身份不会漂移，也不需要姿态**。

**审片拿到的四条意见里，两条是我本该照做的规则。** 翻身那一拍我用侧视图硬转 180 度，尾巴自然朝上翘着——而 `layer-contract.md` 明写姿态变化要用两张图交叉淡入。我读过也引用过这条，但在测出「姿态生成不出来」之后，就默认所有姿态问题只能靠代码变换解决，再没回头试。重试三种说法，成功那条的关键差别是**把相机位置说死了**（「从正上方俯视」），另两条描述身体状态的都失败。**指定视角比描述姿态有效**——这条本该在测姿态那轮就试出来。

## What Worked

**代码驱动的运动足以撑住判据 2，而且不勉强。** 两支片子最长静止画面分别是 2.00 秒和 4.00 秒，对照上一支片子的 13.70 秒。做法是每个 scene 两到三个图层各自位移、旋转、缩放、淡入淡出，加相机推拉和次级摆动。**这条成立的前提是放弃「不同动作用不同的图」——把动作交给代码之后才成立的。**

**锚点格式能稳住角色身份，前提是稳定部分逐字重复。** 六张图两组测试全部通过。反过来也验证了：一旦为了强调姿态改写那些部分，一致性立刻塌。**这条规矩是承重的，不是讲究。**

**统一色板写进每一条 prompt 就够了。** 第一版出现过「配角是黑剪影、和主角不像同一套」，把色板逐条写进 prompt 之后，四张背景加八个图层看起来是同一套东西。

**真实产物可以不重绘地进画面。** 片 A 里四张一手产物——流水线图、带时间戳的原话卡、配置与模板的矛盾对照、数据卡——内容一个像素未改，加纸质衬底轻微倾斜后作为 alpha 层进片，文字在 1920 宽的画面里完全可读。

**校验器抓到了两处「看起来在动其实没有事发生」。** s5、s8 原本只有相机推拉和次级循环，被 `validate-manifest.mjs` 以「Hero scene requires meaningful semantic keyframes on a primary layer; camera or idle loops are insufficient」拒掉。**这正是判据 2 想挡的东西，而它是自动挡住的。**

**当场记数据这件事本身有效。** 上一个实验单步耗时那栏是「待补」，因为没当场记。这次每一步开始就记，最后耗时、失败次数、干预分类都是实数。

## What Failed

**姿态控制不是提示词写法问题。** 八个姿态首轮 0/8 命中，重试改语序、改句式、加负向词之后 1/4。这更像是模型对物体概念的先验太强——它知道这个动物长什么样，不太理会你要它做什么。后来发现「指定视角」比「描述姿态」有效，但那也只是把命中率从接近零抬到偶尔可用。

**白配白的主体抠不出来。** 白纸、白表盘、浅色房子在浅色背景上，分割会把主体当背景吃掉。片 A 的两个文档图层和重生成的钟都是这么废掉的。解法是不再生成，改用合成衬底——但那意味着这类元素本质上生成不了。

**一次成片作废，代价是 19 张图和约 145 分钟。** 第一版片 B 判据 1、2 都过了，但画面没有讲旁白在讲的事——旁白说主角低头让另一只动物爬上背驮它过河，画面里两只动物并排站着。**判据是我自己定的，而且定得太容易过。**「没有静止超过 8 秒」只能挡住幻灯片，挡不住「动是动了但没演对」。真正该测的那条不好机器判定，我没写进判据。

**我三次在没有实测的情况下下判断，三次都反了。** 一次是信官方文档不信仓库里的一手记录；一次是没读原文就断言角色一致性方案靠不住；一次是把「姿态生成不出来」这个阶段性结论扩大成了普遍限制，导致翻身那一拍从一开始就用了错的做法。**三次的共同点是拿一个结论去替代下一次的观察，三次都是作者一句话掰回来的。**

**同一条规则被复制成多份，改一份不会有人提醒你还有另一份。** provider 白名单在 `preflight.mjs` 和 `validate-manifest.mjs` 各有一份；「合成图能不能当图层」的约束在 `qa.md` 和分层契约的 alpha 校验里各有一条。三次都是同样的报错形状，但第三次那条规则是对的——它挡的是「把整张合成图当图层用」，该迁就规则而不是改规则。**分辨这两者靠的是规则想防什么，不是报错长什么样。**

**「精美」这条判据从一开始就不敢立，最后也确实没立起来。** 作者无美术背景，只能给主观分。所以两条硬判据都是机器可判的，而片子好不好看，仍然只能靠人看一遍说「这个动画做得非常奇怪」。
