# 叙事与平台落点

## 写前先填六格

从已确认的事实中填，不足就问作者：

1. 读者一开始处在什么具体困境；
2. 作者这次要做什么，为什么要做；
3. 最后做成了没有；
4. 一个真实转折：失败、否决、代价或判断改变；
5. 读者现在能拿走什么，哪些仍未开放；
6. 结论不能外推到哪里。

先用第 1–3 格写总体说明，再用第 4 格推进正文。不得先抛 Film A、QA、重做、内部工具或数字，再补它们是什么。

## 长文骨架

`总体问题和结果 → 具体卡点 → 尝试为何失效 → 判断转向 → 代价与结果 → 可带走成果 → 边界`。

方法、数字、工具只在它们推动这条线时出现。正文不按 README 的 `Setup / Results / What Worked` 顺序复述，不逐行复读表格。表格只给读者核对。

## 平台差异

- **Site**：开头先给总体问题、验证对象和结果；再用可验证场景引入。英文按论证组织，中文可按时间推进。
- **公众号**：开头先说实验对象、旧卡点和结果，再进返工或失败现场。每节回答“为什么原来不行，后来为什么改”。
- **小红书**：第一屏可用具体反差，但反差里必须带实验对象；第二屏补读者处境和总体结果。数字必须有参照物。

## 反汇报检查

通读后问：

- 把每段首句改成“X 是 Y”，文章是否几乎不变？若是，删介绍句，改成动作、判断或后果。
- 读者是否先知道“做什么、为何做、是否做成”，才遇到内部名词？
- 每一节是否推进一个因果，而不是介绍一个文件、工具或指标？
