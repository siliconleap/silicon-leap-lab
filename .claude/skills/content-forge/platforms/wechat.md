# 微信公众号

## Role

中文深度长文。这是四个渠道里**唯一允许把完整推演过程写出来**的地方：小红书必须在第一屏给冲突，site 要克制可引用，视频要留悬念，只有这里可以按事情发生的顺序，把从困惑到结论的路径完整走一遍。

读者是主动点进来的，他们愿意读完，前提是每一段都在往前走。

## Emphasis

- 按时间顺序推演，不按论文结构组织。先发生什么，再发现什么，最后想明白什么。
- 结论可以放在后面，但**开头必须给出冲突**——读者要知道这篇值不值得读完。
- 关键判断处写出当时的依据和不确定，不要只给结果。
- 数字、文件名、报错原文照抄，不转述。
- 失败路径完整保留，包括走错的那一段。

## Layout Rules

- 标题 20 字以内，副标题可选。不用「深度解析」「保姆级」这类前缀。
- 用小标题分节，每节 300-600 字。小标题用判断句或问句，不用「一、背景介绍」。
- **每段不超过 3 行**（手机屏幕宽度）。长段落是公众号最大的杀手。
- 中文与英文、数字之间加半角空格：`用 Claude Code 跑了 30 天`。
- 代码块单独成段，超过 15 行的截断并标注省略。
- 结尾给复现路径（仓库链接 / 实验目录），不写「欢迎关注」。

## 视觉资产

公众号的图承担的是**呼吸感**，不是信息主体——正文已经能把话说完，图负责让人读得下去。

| 项 | 值 |
| --- | --- |
| 数量 | 3-6 张，每 400-800 字一张 |
| 宽度 | 正文图 1080px 渲染（显示宽度 ≤640px），不低于 320px |
| 头条封面 | 900 × 500 |
| 次条封面 | 200 × 200 |
| 底色 | 深色 `#1a1a19`（终端质感）或浅色 `#fcfcfb`，一篇之内不混用 |
| 文字 | 深底 `#f0eee6` / `#a8a49c`；浅底 `#0b0b0b` / `#52514e` |
| 状态色 | 通过 `#0ca30c` · 警告 `#fab219` · 失败 `#d03b3b`，**必须配图标和文字** |
| 分类色 | 固定顺序 `#3987e5` `#d95926` `#199e70`，超过三类合并成「其他」 |

**每张图必须带图注**，一行小字写清「这是什么 + 来源」。这是公众号的行业惯例，也是可信度的一部分：

```markdown
![](assets/02-validate-output.png)
*图 2：validate.sh 抓出四处死链，来源为本次实验实际输出*
```

**生成方式**：写 HTML 源到 `drafts/wechat/assets/`（带 `<meta name="render-size" content="1080x608">`，封面用 `900x500`），跑 `scripts/render.sh` 渲染 PNG。HTML 是源，PNG 是产物。

**图里同样要脱敏**：用户名、邮箱、绝对路径换占位符。

真实终端截图不生成，列进缺口清单。

## Acceptance Checklist

- 标题 20 字以内，无「深度解析」「保姆级」类前缀。
- 开头 3 行内给出冲突，不铺垫背景。
- 每段不超过 3 行；小标题是判断句或问句。
- 中英文、中文与数字之间有半角空格。
- 3-6 张配图，**每张有图注**（内容 + 来源），HTML 源和 PNG 都在 `drafts/wechat/assets/`。
- 数字全部可追溯到 README 的 Data 段。
- 保留了失败路径，不只讲成功。
- 结尾是复现路径，不是关注引导。
- 结论为空时明确标注待补，不代写观点。
