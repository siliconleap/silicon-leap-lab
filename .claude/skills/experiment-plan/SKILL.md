# Experiment Plan

输入一句话选题，输出一个能照着跑的实验目录。

## 职责分层

这个 skill 不亲手写骨架。三层分工，越确定的越往下放：

| 层 | 谁 | 负责 |
| --- | --- | --- |
| 确定性 | `scripts/` | 建目录、七段标题、内容骨架、产物时间轴、会话时间线、校验 |
| 可推断 | 本 skill | 选题审查、判据、步骤表、数据字段、内容骨架初稿 |
| 真正的决策 | 人 | 选题值不值得做、背景是否可公开、判据、结论 |

**凡是确定性的东西一律交给脚本**，模型不复述、不重写、不"顺手改进"。七段标题是 `content-forge` 的解析接口，模型手打就有漂移风险，所以由脚本生成。

## 边界

设计**过程**，不预设**结果**。

- 步骤、交付物、要记什么数据 → 这里定
- 结论、判断、实验跑出来是什么 → 跑完才有，不许预填

脚本生成的 `Log` / `Data` / `What Worked` / `What Failed` / `Conclusion` 五段只有标题和提示注释，**不许填内容**。预填等于污染实验——人会不自觉地往预设的答案上靠。

不要编造用户没说的工具、版本、环境。缺什么就问。

## 流程

### 第一步：审选题

一句话选题通常不够开工。先确认这四件事，缺了就问，不要猜：

1. **对象**——测什么工具 / 什么方法 / 哪几个之间对比
2. **任务**——用什么具体任务去测。必须是真实任务，不是 toy example
3. **判据**——怎么算做完了、怎么算某一方赢了
4. **反直觉点**——你预期会推翻什么常见说法

第 4 项是选题价值的核心，和 `content-forge` 判断内容价值用的是同一个标准。如果用户答不上来，直说：这个选题可能只能产出一篇平庸的工具介绍，建议换角度或换对比对象。不要硬着头皮往下做。

**拒绝教程式选题。** 「XX 怎么用」「XX 使用教程」不是实验。遇到这类输入，改写成结构性问题再确认：

| 输入 | 改写 |
| --- | --- |
| Claude Code 怎么用 | 同一个真实需求，Claude Code 和 Cursor 谁的返工次数更少？ |
| MCP 介绍 | MCP 能不能替掉我现在手写的三个脚本？代价是什么？ |

### 第二步：定规模

第一个实验不要设计成 30 天。

单次实验的合理规模：**半天到三天能跑完，产出 3-5 条量化数据**。大主题拆成多个实验，用 monorepo 交叉引用。

如果用户的选题明显超过三天，提出拆分方案再继续。

### 第三步：生成骨架（调脚本，不要手写）

```sh
scripts/init-experiment.sh <slug> "<标题>"
```

路径相对本 skill 的 base directory。脚本会：

- 从 git 仓库根定位 lab 仓库，**校验存在 `experiments/` 目录**，否则拒绝执行——这一条保证不会在别的仓库里建出实验目录
- 用当前年月拼出 `experiments/YYYY-MM-<slug>/`
- 目录已存在则报错退出，不覆盖
- 写 `README.md`（七段标题逐字生成）和 `plan.md`（含产物时间轴）
- 把创建的路径打到 stdout

slug 用 kebab-case 英文。脚本会校验格式，不合法直接拒绝。

**不要绕过脚本手写这两个文件。** 手写就是漂移的开始。

### 第四步：填语义内容

脚本给的是骨架，模型往里填这些：

**`README.md`**——只填 `Question` 和 `Setup`，填完把对应的提示注释删掉。其余五段一个字都不许动。

**`content-outline.md`**——这是内容的开跑前骨架，不是实验结论。填 `已知背景`、`想回答的问题`、`读者与价值`、`已知困难与边界` 和 `预期叙事骨架`；只能使用此时已经确定的事实。作者确认后填写「已确认：是；日期」，再开跑。

另外留两个空节，跑完再填，开跑前一个字都不许写：`预期认知`（这次想验证或推翻哪几条判断）和 `实践清单`（做了什么 / 是否有效 / 是否可复制）。两节都在 `content-forge` 的简报和平台稿里承重，所以位置要在开跑前占好——不是让你预测答案，是逼你在设计实验时就想清楚：这次做的事，最后要能一条条填进这两张表。

**`plan.md`**——填这几节，删掉填过的提示注释：

- `判据`——第一步确认的三条，写死
- `预期反直觉点`——第一步的第 4 项。**若为回溯补记**（实验已经跑完才补剧本），删掉本节改写成「实际发现」，并在文件顶部标明是补记
- `步骤`——每步的交付物、记什么数据、录哪段。「记什么数据」不许留空，校验脚本会抓
- `数据字段`——按实验实际需要增删，但至少覆盖脚本预置的六项
- `录制清单`、`已知风险`

`产物时间轴`那一节由脚本生成，**不要改**。

### 第五步：校验（报告前必须跑）

```sh
scripts/validate.sh <实验目录>
```

**退出码非零就必须修完再报告，不许带着 FAIL 交付。**

脚本查的是确定性的东西：目录名格式、七段标题逐字有序、`plan.md` 步骤表空单元格、`drafts/` 相对链接目标是否存在、结论为空时初稿是否标了待补。

刚生成的骨架跑校验必然报「步骤表有空单元格」——那是提醒你还没填，填完就过。

查不了的部分靠人：是不是教程腔、反直觉点成不成立、结论有没有价值。

## 跑完之后：捞会话时间线

实验跑完、交给 `content-forge` 之前，跑这个：

```sh
scripts/extract-timeline.py \
  ~/.claude/projects/<项目目录> \
  ~/.codex/sessions/<年>/<月> \
  --cwd <仓库路径片段> --since <开跑日期> \
  > <实验目录>/notes/session-timeline.md
```

**这一步不是可选的。** 对话式工作在终端里留不下操作过程——`recordings/` 是空的
才是常态。但每一句真人输入都带时间戳：决策、犹豫、中断、返工全在会话记录里。
这是 `notes/` 里唯一一类事后还能补、且补出来仍算一手证据的素材。错过的话，
`content-forge` 只能拿数据卡和示意图撑视频。

两个参数不许省：

- `--cwd`——Codex 按日期存会话，不按项目存。不过滤就会把当月其他项目的对话抄进
  这个实验的记录里，而这份产物是要公开的。
- `--since`——开跑日期。更早的属于上一次实验。

脚本已经滤掉不是人说的话（系统注入、agent transcript 回灌），和「继续」「可以
提交」这类零信息指令。**跟本次选题无关的话题不在这里删**——那是叙事判断，留给
`content-forge` 选素材时做。raw 记录就该是 raw 的。

### 第六步：报告

- 脚本建了哪些文件（用脚本的 stdout，不要凭记忆写路径）
- 校验结果，剩余的 WARN 是什么
- 预计耗时和步骤数
- 哪些前提还没确认（工具版本、账号、环境）
- `content-outline.md` 是否已由作者确认；未确认时不得开始实验
- 第一步具体从什么动作开始

## 硬约束

- 骨架必须由脚本生成，模型不手写七段标题和产物时间轴。
- 五个结论类段落只留标题，不预填。
- 实验前必须完成并由作者确认 `content-outline.md`；背景可以预写，实验发现和结论不可以。
- 不编造用户没确认的工具、版本、环境。
- 教程式选题先改写，改写不掉就说清楚为什么这个选题不值得做。
- 每个步骤必须有交付物。说不出交付物的步骤是想象，不是计划。
- 单次实验控制在三天内。超了就拆。
- 报告前必须跑 `validate.sh` 且退出码为 0。
- 跑完实验后必须捞 `notes/session-timeline.md`，且必须带 `--cwd`。

## 相关

- 跑完之后生成初稿：`content-forge` skill
- 实验产生了可复用成果时：在 README 追加可选的 `## Artifacts` 段写指针，不要把成果拷进实验目录
