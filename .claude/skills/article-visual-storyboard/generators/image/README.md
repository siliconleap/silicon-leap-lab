# 图像生成器

备用通道。调外部文生图 API 出画面。

## 现状：默认不用

**当前所有画面走 SVG。** 这个目录先占位，写清楚什么时候才值得切过来。

## 什么时候用它

SVG 画不了的东西：

- 有质感的场景（纸张纤维、光影、材质）
- 具体的人物形象、表情
- 写实或半写实的物件
- 风格化插画（水彩、油画、拼贴）

## 什么时候不要用

**示意图、结构图、流程图、图标——一律用 SVG。** 理由：

- 文生图画不准结构。要「三个方框两个箭头」，它给你四个方框一个箭头
- 图里不能出现可信的真实文字。模型写出来的字是乱码或错字，而这套流程的
  核心恰恰是把真实原话嵌进画面
- 抽卡不可复现。同一个 prompt 两次结果不同，源和产物脱钩
- 要账号、要配额、要计费

## 已探测的通道

| 通道 | 状态 | 说明 |
| --- | --- | --- |
| 腾讯云 `aiart` / `TextToImageLite` | 可用 | 凭据复用 `TENCENT_CLOUD_SECRET_ID` / `_KEY`，TC3 签名同 TTS |
| 腾讯云混元生图 `SubmitHunyuanImageJob` | 需开通 | 返回 `ResourceInsufficient`，要在控制台开后付费 |
| `gbro-collage-broll` | 未接 | 外部 skill，Gemini 首尾帧生成 5 秒竖版拼贴 B-roll，需 Codex 环境 + `GEMINI_API_KEY` |

## 接进来的话要守的规矩

1. **产物一律标「示意」。** 生成的画面不能冒充证据，见 SKILL.md 的证据强度表
2. **prompt 进 git。** 它是源，跟 SVG 一个道理。存成 `<编号>-prompt.txt`
3. **不生成看起来像截图的东西。** 假终端、假报错、假聊天记录，一律不许
4. **风格要能对齐 style-bible。** 一组图里 SVG 和生成图混用时，配色和构图必须统一，
   否则看起来像两篇文章拼起来的
