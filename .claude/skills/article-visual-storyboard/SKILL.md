# Article Visual Storyboard

把叙事拆成画面，再把画面画出来。

输入是一篇写好的稿子（或一份实验记录 + 分镜脚本），输出是一组编号的图，
每张对应叙事里的一拍。

## 为什么单独做一个 skill

配图不是「文章写完顺手加两张」。它有自己的一条链：

```
叙事      →  storyboard.md   哪几拍需要画面，每拍讲什么
风格      →  style-bible.md  这一组图长什么样，颜色线宽字号统一
单张      →  scene.md        这一张的构图、元素、要嵌的真实文字
生成      →  generators/     SVG 源 → PNG 产物
```

四层各自可换：换风格不动叙事，换生成器不动构图。`content-forge` 只负责把
文字产出到各平台，画面交给这里。

## 边界

- **画面服务叙事，不是装饰。** 一张图讲不出这一拍在说什么，就是没用的图，删掉比留着好。
- **不产出观点。** 图里出现的判断句必须来自稿子或作者原话，不许自己发挥。
- **不伪造证据。** 图里的终端输出、报错、时间戳、数字，只能来自真实记录。编不出来就别放，放了就是造假。
- **源是文本。** SVG / HTML 进 git，PNG 是产物。改图改源重渲染，不用图形工具改 PNG。

## 证据强度：这是这套东西最容易搞砸的地方

示意图天然是「画出来的」，但**图里嵌的真实文字仍然是证据**。两者可以共存，
而且共存的效果最好：

| 做法 | 证据级别 | 说明 |
| --- | --- | --- |
| 图形示意 + 嵌入真实原话/时间戳/报错 | **一手** | 图是画的，字是真的。首选 |
| 纯图形示意，无真实内容 | 示意 | 用于概念、比喻、结构，画面上要能看出是示意 |
| 图形 + 编造的「示例」终端输出 | **禁止** | 看起来像截图的假证据，比没有图糟糕得多 |

所以画终端窗口、文档、聊天气泡这类容器时，**里面装的必须是真东西**：
`notes/session-timeline.md` 的原话、git 提交信息、真实报错、真实数字，
并且把来源（文件名、时间戳）也画进去。

## 流程

### 第一步：确认风格

读 `templates/style-bible.md`，与用户确认或让用户选一版。**风格先定，再画图**——
画到第五张才改风格，前四张全得重来。

style-bible 是可替换的配置，不是本 skill 的一部分。同一套流程可以配手绘线稿、
纸片拼贴、等距插画、极简几何——换文件即可。

### 第二步：列 storyboard

按 `templates/storyboard.md` 列出全部画面：编号、对应叙事的哪一拍、一句话
说明这张要让人看懂什么、证据级别、要嵌哪些真实文字。

**先列全再画。** 一张一张边画边想，会画出十张风格不一致、信息密度忽高忽低的图。

列完交用户过一遍意象，再动手。改一行字比改一张图便宜。

### 第三步：逐张写 scene 并画

每张按 `templates/scene.md` 写清构图，再生成源文件。生成器见 `generators/`。

### 第四步：渲染与检查

```sh
generators/svg/render.sh <assets 目录>
```

渲染完**必须逐张看过**。不看图直接交付是这套流程里最容易出错的一步——
SVG 语法正确不等于画面能看，路径写错只会画出一团乱线，而脚本不会报错。

逐张对照检查清单（见下）。不合格的重画，不要将就。

## 硬约束

这些是踩过坑总结的，不是审美偏好：

- **手绘滤镜只加在图形上，文字不加。** `feTurbulence` + `feDisplacementMap` 会把
  文字扭糊。分组：图形放进带 filter 的 `<g>`，`<text>` 放在外面。
- **主体占画面 70-80%。** 元素太小、四周大片留白，放进视频就是「空」。这是第一版
  三张废稿的共同死因。
- **一张图只讲一件事。** 讲不完就拆成两张。塞满元素的图等于没有重点。
- **文字最小 26px（1920 宽）。** 手机上看视频，再小就没了。
- **颜色按语义固定**，见 style-bible。同一个意思在十张图里必须同色。
- **不写用户名、邮箱、绝对路径。** 图比正文传播更广，且改不了。
- **图里的中文标注要短。** 一行不超过 14 字，长句留给旁白和正文。

## 检查清单

每张图渲染后逐条过：

- [ ] 不看正文，能看出这张在讲什么吗
- [ ] 主体是否占到画面 70% 以上
- [ ] 嵌入的真实文字是否与原始记录逐字一致，来源是否标了
- [ ] 有没有编造的终端输出、报错或数字
- [ ] 文字是否清晰（没被滤镜扭糊）、字号是否够大
- [ ] 颜色语义是否与 style-bible 一致
- [ ] 有没有泄露用户名、邮箱、绝对路径

## 与其他 skill 的关系

| Skill | 关系 |
| --- | --- |
| `content-forge` | 上游。它产文字和 `scenes.md`，画面需求交给本 skill |
| `experiment-plan` | 更上游。`notes/session-timeline.md` 是嵌入真实文字的主要来源 |
| 视频构建 | 下游。`content-forge/scripts/build-video.py` 把图按配音时长铺成成片 |

本 skill 不负责配音、剪辑、发布。
